2. 默认删除含两项任务的分类，任务移入未分类，刷新仍为 1/3；撤销分类恢复原结构。
3. 生成入口只必填目标，其他选项折叠；生成及转换按钮写出自包含提示词，内容包含有效协议示例。转换提示明确保留资源、顺序、固定日期、信息不足先问。两者进入同一导入窗口。
4. 编程样例以“说明 + json代码块 + 说明”输入成功。已有两项未知时长待办按30分钟估算占用10/16，60分钟预算 + 工作日模式将任务安排到10/19、10/20。阶段、说明和资源可见。
5. 在阶段视图改任务标题、说明、时长后取消，正式任务仍为原三项1/3；重新预览可取消选择任务和修改名称。双击确认仅新增1计划3任务，日期与预览一致。
6. 导入任务可完成；另一项从10/19手动推迟至10/21，刷新后仅在新日期出现，原计划/来源保留。任务编辑的“更多信息”能看到说明、阶段及资源链接。
7. 整计划删除确认显示3条关联、1条完成、2条今日及以后未完成。选择全删时未额外勾选不能确认；实际执行“只删今日及以后未完成”，完成项保留为1/1。刷新、最近删除、备份预览均正确。

10. 错误版本有明确 format 错误；修复提示包含错误和待修复输入，未包含原有样例任务文本。

## 交付边界

- 仅 Edge 桌面与响应式视口实测；没有 Android/iOS 真机、真实软键盘、系统 PWA 独立窗口或 file:// 重测，不能宣称全设备通过。
- 空间不足/保存失败/并发变化由可控模型测试注入，未填满真实浏览器存储。
- 保留旧 day 整组模式；只有 sequence 模式按任务预算分配日期。fixed 不改日期，冲突需明确处理。依赖仅支持前序任务，可在同日先后，不做工时级依赖、自动拆分、特殊休息日或自然语言理解。
- 缺少预计时长使用明确默认估算，不等于实际用时承诺。确认过的日期映射保存后不会因刷新自动重新排期；手动推迟不更新原计划的理论结束日，也不顺延全计划。
- 撤销导入不回滚其他修改；有完成记录需额外确认，有关联删除副本需先撤销删除。撤销导入本身不再进入最近删除。
- 保留用户原服务和浏览器数据。本轮专用测试服务已停止、临时视口已恢复；静态 dist 仅为本地打包，不代表 GitHub Pages 更新。
