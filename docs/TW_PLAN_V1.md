# TW_PLAN_V1 · 协议、兼容扩展与边界（2.3）

Today Work 把计划，变成今天要做的事。用户自行把提示词发给任意 AI，再把 JSON 粘贴回来；应用不连接 AI、不执行输入内容。此文档先于本轮实现编写。

```json
{
  "format": "TW_PLAN_V1",
  "planName": "英语学习计划",
  "goal": "提高听力与阅读能力",
  "categories": ["听力", "阅读"],
  "days": [
    {"day": 1, "tasks": [{"title": "完成听力练习并整理错题", "category": "听力", "estimatedMinutes": 30, "priority": "high", "note": "先完整听一遍，再核对答案"}]},
    {"day": 2, "tasks": [{"title": "阅读一篇文章并整理表达", "category": "阅读", "estimatedMinutes": 40, "priority": "medium", "note": ""}]}
  ]
}
```

## 输入与校验

- 接受纯 JSON、单个 json/无语言代码块，以及前后附解释的单个计划 JSON。识别字符串与转义后的配对括号；多个候选计划、错误 JSON 或不完整结构拒绝猜选。不从自然语言或表格猜测任务。
- `format` 必须恰为 `TW_PLAN_V1`；`planName` 必填非空，最多 100 字符。`goal` 可省略，最多 2000 字符。
- `categories` 为 1–40 个不重复的非空字符串，每个最多 40 字符；名称去除首尾空白后比较。
- `days` 为 1–366 项，`day` 必须为整数并依次等于 1、2、3……。每个执行日 1–100 项任务，总计不超过 2000 项。
- `title` 必填非空，最多 160 字符；`category` 必须在声明分类中。
- `estimatedMinutes` 可省略或为 null，否则为 1–10080 的整数（分钟）。未知时长保持未知。
- `priority` 仅 `low`、`medium`、`high`，省略时为 `medium`。`note` 可省略，最多 4000 字符。
- 原始输入最多 1 MiB UTF-8；字符串限制按 JavaScript UTF-16 长度。拒绝未定义字段、重复统计字段。2.3 的可选扩展见下；所有原有合法输入仍有效。
- 所有内容为普通文本；展示时转义，不执行 HTML、脚本或链接指令。

## 2.3 可选扩展

- 计划 `scheduling`: day（缺省，原执行日整体映射）、sequence（任务按原顺序结合预算安排）、fixed（每项任务有固定日期）。
- 计划 `deadline`: 有效 YYYY-MM-DD；Day 可选 `stage`：非空阶段名 ≤100 字符。
- 任务 `stage`：非空阶段名 ≤100，优先于 Day.stage；`description`：非空说明 ≤4000，独立保留原 note。
- 任务 `resources`: 最多10个 `{title,url}`，title非空≤160、url≤2000，只允许有效完整 http/https。
- 任务 `date`: 有效固定日期，只允许 sequence/fixed；fixed 每项必填。不能在 day 模式携带日期后静默忽略。
- 任务 `id`: 计划内唯一非空字符串≤80；`dependsOn`: 最多50个已在前文出现的任务 id，不允许缺失、倒序或循环。依赖允许同日先后，不要求自动增加一天。

```json
{
  "format": "TW_PLAN_V1",
  "planName": "论文写作",
  "categories": ["写作"],
  "scheduling": "sequence",
  "deadline": "2026-11-30",
  "days": [
    {"day": 1, "stage": "提纲", "tasks": [{"id": "outline", "title": "列出研究问题", "category": "写作", "estimatedMinutes": 30, "description": "只使用已确认的研究范围"}]},
    {"day": 2, "stage": "初稿", "tasks": [{"title": "撰写方法提纲", "category": "写作", "estimatedMinutes": null, "dependsOn": ["outline"], "note": "时长待确认"}]}
  ]
}
```

所有日期均由用户/已有讨论明确给出；提示词不让 AI 凭空发明实际日期。资源未知就省略，关键内容不明先询问。生成、转换和修复提示词调用同一份完整字段规则及有效示例，无须 AI 访问网站。

## 调度

执行天数是实际安排任务的天数，不是自然日跨度。day/sequence 的无固定日期任务由本地执行星期决定；date 是明确固定点，deadline 是不得静默突破的约束。不支持特殊休息日。

开始日期使用浏览器本地日历（1900–9999 年）。勾选的星期是唯一依据，快捷选项只批量设置星期。至少选一个星期。无固定日期的开始日不符合时，向后找到首个可执行日。day 保留 Day 整体映射；sequence 按原任务顺序放入有剩余预算的日期，允许一个 Day 分配到多天、多个 Day 共用一天。阶段、任务顺序、依赖保留，不捏造拆分内容。跨月、跨年照常计算；超出支持日期范围报错。

可设置每日最大任务数（1–10000）与最大预计分钟（1–100800），留空为不限。按目标日期**已有未完成任务 + 本次新增任务**计算，多个已有计划一起占用预算；已完成任务不再占用，实际用时不参与。未知时长默认每项30分钟，可修改默认值或具体任务；显示未知项数、估算和“无法完整判断”，必须明确确认。导入任务存储预览使用的 estimatedMinutes，并以 estimatedFromDefault 标记；计划原文仍保留 null。

单项超过预算时不拆分、不无限跳日期：显示超额原因，须修改时长、手动拆分或明确允许超额。fixed 和 sequence 的固定点保持实际日期，预算/星期冲突警告并需明确保持；早于开始日/前序任务的固定点阻止导入。超过截止日阻止确认，只能用户明确修改期限、预算或任务数量后重新预览。不会自动延长期限或重排已有正式任务。

## 导入、关联与兼容

解析、编辑、任务取消选择、规则修改、预览及取消均不写入正式数据。确认时重新读取最新本地数据，校验完整预览签名/映射；相关负担变化则拒绝保存并要求重新检查。正式写入直接使用已确认的日期映射及估算值，再一次 `localStorage.setItem` 保存计划与任务；失败不更新当前界面数据。默认追加，保留原任务及完成状态。重复提交受按钮锁和完成态保护；同内容仅改名称/目标也会提示重复，须显式选择作为新计划追加。

可选根字段 `plans` 保持。记录含本地 ID、规范化协议、创建时间、规则和日期映射。旧记录继续按原 Day 映射校验；新记录含 scheduleVersion:2，mapping 包含 day/date/taskIndexes，逐项覆盖、不重复且保留原顺序。新记录不以空数据库重新排期验证，避免其他计划占用导致的真实映射在恢复时被误判。

任务含 sourcePlanId/sourceDay/sourceTaskId；手动加入今日或推迟时保留关联。推迟只移动指定未完成实例，不能移动已完成历史，不顺延全计划。成功页及设置提供撤销导入，只移除该计划关联数据；存在完成记录时额外确认，存在关联删除副本时先撤销删除。旧备份、单日导入及现有删除备份均兼容。详见 [2.3 流程和边界](AI-IMPORT-2.3.md)。

旧“导入今日计划”仍接受 `{ "date": "2026-10-20", "categories": [{ "name": "学习", "tasks": ["阅读一章"] }] }`（date 可省略）。这是单日兼容入口，不是 TW_PLAN_V1 多日导入。

首版不提供结束日期预测、进度落后判断或大型目标系统。预览结束日期仅代表当前规则下的实际排期末日。
