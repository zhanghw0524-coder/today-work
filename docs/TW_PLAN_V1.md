# TW_PLAN_V1 · 首版协议与边界

Today Work 把计划，变成今天要做的事。用户自行把提示词发给任意 AI，再把 JSON 粘贴回来；应用不连接 AI、不执行输入内容。此文档先于本轮实现编写。

```json
{
  "format": "TW_PLAN_V1",
  "planName": "英语学习计划",
  "goal": "提高听力与阅读能力",
  "categories": ["听力", "阅读"],
  "days": [
    {"day": 1, "tasks": [{"title": "完成听力练习并整理错题", "category": "听力", "estimatedMinutes": 30, "priority": "high", "note": "先完整听一遍，再核对答案"}]},
    {"day": 2, "tasks": [{"title": "阅读一篇文章并整理表达", "category": "阅读", "estimatedMinutes": 40, "priority": "medium", "note": ""}]}
  ]
}
```

## 输入与校验

- 只接受纯 JSON 或单个外层 \`\`\`json 代码块（也接受无语言标识的单个代码块）。不从说明文字、自然语言或表格猜测内容。
- `format` 必须恰为 `TW_PLAN_V1`；`planName` 必填非空，最多 100 字符。`goal` 可省略，最多 2000 字符。
- `categories` 为 1–40 个不重复的非空字符串，每个最多 40 字符；名称去除首尾空白后比较。
- `days` 为 1–366 项，`day` 必须为整数并依次等于 1、2、3……。每个执行日 1–100 项任务，总计不超过 2000 项。
- `title` 必填非空，最多 160 字符；`category` 必须在声明分类中。
- `estimatedMinutes` 可省略或为 null，否则为 1–10080 的整数（分钟）。未知时长保持未知。
- `priority` 仅 `low`、`medium`、`high`，省略时为 `medium`。`note` 可省略，最多 4000 字符。
- 原始输入最多 1 MiB UTF-8；字符串限制按 JavaScript UTF-16 长度。拒绝未定义字段（包括实际日期、重复统计字段），避免误以为这些字段生效。
- 所有内容为普通文本；展示时转义，不执行 HTML、脚本或链接指令。

## 调度

执行天数是实际安排任务的天数，不是自然日跨度。协议不含日期或休息日；由本地执行规则决定。

开始日期使用浏览器本地日历（1900–9999 年）。勾选的星期是唯一依据，快捷选项只批量设置星期。至少选一个星期。开始日不符合时，向后找到首个可执行日。每个 Day 整体对应一个日期，不拆分、不重排原任务；跨月、跨年照常计算。超出支持日期范围报错。

可设置每日最大任务数（1–10000）与最大预计分钟（1–100800），留空为不限。按目标日期**已有任务 + 新增任务**检查；实际用时不参与。存在未知预计时长时提示“无法完整判断”，不能声称没有超限。超限或时长无法判断时必须明确选择保持安排，或修改规则。首版不自动拆分、扩容、重排，不支持特殊休息日。

## 导入、关联与兼容

解析、规则修改、预览、取消均不写入正式数据。确认时重新读取最新本地数据、重新检查冲突与上限，再一次 `localStorage.setItem` 保存计划记录与全部任务；失败不更新当前界面数据。默认追加，保留原任务及完成状态。重复提交受按钮锁保护；相同规范化 JSON 再次导入需显式确认，不按计划名称误判。

新增可选根字段 `plans`。每个记录含本地 ID、原始规范化协议、创建时间、规则和 Day → 日期映射。任务含 `sourcePlanId`、`sourceDay`、`sourceTaskId`；同一原任务手动转入今日时这些字段保持不变，逻辑任务以 `sourceTaskId` 去重。计划不自动顺延。旧版不含 `plans` 的数据、备份仍可使用；现有备份包含这些新增字段。

旧“导入今日计划”仍接受 `{ "date": "2026-10-20", "categories": [{ "name": "学习", "tasks": ["阅读一章"] }] }`（date 可省略）。这是单日兼容入口，不是 TW_PLAN_V1 多日导入。

首版不提供结束日期预测、进度落后判断或大型目标系统。预览结束日期仅代表当前规则下的实际排期末日。
