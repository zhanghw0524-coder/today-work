# Today Work 2.3 · AI 计划导入实施约定

本轮仅本地实现及验收，不推送、不发布。复用 TW_PLAN_V1、StudyStorage、TodayWorkPlans 和现有删除模型，不连接 AI。

## 两个入口

“还没有计划”只必填目标；更多选项含当前基础、开始日期、执行天数（默认 14）、每日分钟（默认 30）、执行星期、其他要求。生成自包含提示词并复制到外部 AI。

“已经和 AI 聊好了计划”复制转换提示词到原对话：保留目标、阶段、顺序、资源、时间和依赖；缺少信息先询问或在 note 明确标记未知，不编造资源、日期或目标。返回内容进入同一个导入窗口。

## 协议扩展（保持 TW_PLAN_V1）

原必填字段及限制保持。以下均为可选字段；未知字段仍具体报错。

- 计划 `scheduling`: `day`（默认，旧版整个执行日映射）、`sequence`（按任务顺序分配预算）、`fixed`（每项任务必须有实际日期，绝不自动移动）。
- 计划 `deadline`: 有效 YYYY-MM-DD，可省略。用户在预览中明确修改/清空才改变此约束。
- Day `stage`: 阶段名，最多 100 字符。
- 任务 `stage`: 阶段名，最多 100 字符；优先于 Day.stage。
- 任务 `description`: 普通文本最多 4000 字符，与原 note 同时保留。
- 任务 `resources`: 最多 10 个 `{title,url}`，title 最多 160，url 最多 2000，仅完整 http/https。不得虚构链接。
- 任务 `date`: 有效固定日期，可用于 sequence 的固定点；day 模式不能携带实际日期（需明确改用 sequence/fixed）。
- 任务 `id`: 计划内唯一文本 ID，最多 80 字符；`dependsOn`: 最多 50 个前序任务 ID，只允许已出现的任务，依赖可在同一天但不会晚于当前任务。

原始输入最多 1 MiB，1–366 个连续 Day、每 Day 1–100 项，总任务最多 2000，分类最多 40。支持纯 JSON、代码块及前后说明；只从结构完整、括号及字符串正确配对的 JSON 对象提取。遇到多个候选计划拒绝猜测，遇到错误结构具体报错；不解析自然语言或表格。

## 排期与预览

按本地日历日期计算。星期快捷选项只设置同一组星期勾选。

- day：保留原执行日，不拆分。原有预算提示及显式保持安排继续兼容。
- sequence：按原顺序逐项放入最早可执行日期，已有未完成任务和本次已放入任务一起占用每日预算；已完成任务不再占用预算。保留阶段和依赖顺序，不生成拆分内容。
- fixed：保持每项实际日期；与开始日、执行星期、顺序、预算或依赖冲突时阻止或提示。预算/星期冲突可明确保持；顺序/开始日冲突必须修改输入或规则。
- 固定点遇到前序任务挤占而不可达时阻止导入，绝不自动搬动固定任务。
- 未知时长默认按每项 30 分钟估算，可修改估算值或具体任务时长；明确提示并需确认。保存任务的 estimatedMinutes 使用预览估算值，并标记 estimatedFromDefault，原协议保留 null。
- 单项大于预算时不挪到无限远：停留在候选日并警告，须修改/手动拆分/明确允许超额。
- 超过截止日期时阻止确认。用户可明确修改截止日期以延长、提高预算、减少任务；不自动改变期限。
- 可编辑名称、任务标题/说明/时长，取消选择任务，按阶段和按日期查看；不选的任务不导入，余下 Day 在草稿中重新编号，并检查依赖。取消和预览不保存。

确认时核对最新正式数据与预览签名；如相关负担改变，拒绝保存并更新预览。使用确认后的日期映射及估算，不在写入时另排一遍。计划和任务在同一笔主数据保存中追加；保存失败不留下半计划。重复点击锁定，重复内容默认阻止，用户可明确追加新计划。

日期预览包含“查看日期调整原因”，解释星期跳过、已有负担和本次累计预算导致的移动。只改计划名称或目标不会绕过重复检查。普通任务编辑中可查看说明、阶段与资源，未完成任务的常显菜单可手动推迟；已完成历史不移动。

## 撤销与备份

计划记录保存 scheduleVersion:2 与逐任务映射，校验覆盖所有任务且无重复，不以空数据库重新推导历史排期。原 scheduleVersion 缺省的旧记录按旧规则校验。新旧计划、来源、删除副本均纳入已有备份。

成功页及“设置 → 已导入计划”支持撤销导入；只移除该计划关联任务和计划记录，不回滚其他任务/设置。已有已完成关联任务时额外确认；有尚未撤销的关联删除时先处理删除副本，避免旧副本重新恢复关联。清理仅限本次新建且仍为空、名称未改的分类，不删除既有分类和用户新增内容。

## 启动、更新与验收

本地目录仍为 `job-study-tracker`。双击 `启动 Today Work.cmd`，或运行 `node server.cjs`，打开固定地址 http://127.0.0.1:8765/。文件直开延用旧能力，但本轮未重测，且不能安装 PWA。

应用版本2.3.0，缓存v2.3.1。看到更新提示后先完成编辑，关闭同一地址的所有 TW 标签页和独立窗口，再重新打开；不要清除网站数据。首次缓存就绪后导入、排期、编辑、删除、撤销可离线工作。

本轮不发布。准备现有 GitHub Pages 静态内容：在项目目录执行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/prepare-pages.ps1`，得到 dist。可在自行审核差异、合并远程修改后提交并正常推送仓库根目录源码（现有根目录 Pages 配置），或按原发布方式上传 dist 内容；不要上传个人导出、backups、test-artifacts 和 screenshots。无需修改 Pages 设置，不要 force push。

自动测试及实测边界见 [2.3 验收](../tests/QA-2.3.md)。不将桌面手机视口模拟等同于真机/软键盘或系统安装窗口验证。
