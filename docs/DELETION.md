# Today Work 2.2 · 删除与撤销

本轮以现有纯 HTML / CSS / JavaScript、TW_PLAN_V1、localStorage 与图片 IndexedDB 为基础增量实现。无 AI API、账号、后台服务或计时功能。AI 仍由用户在外部聊天中使用，TW 只负责结构化计划与任务管理。

## 检查结论

原版本任务删除使用常规 `load → 修改当前日期分类 → save → render`，主数据写入链路存在；但电脑端操作按钮默认 `opacity: 0`，需要悬停才能看到，删除只有“×”，不易发现。分类只有重命名，没有删除处理；导入计划没有删除入口；删除后无撤销。旧任务删除入口还直接解引用当前分类和任务，在其他窗口改动后缺少存在性检查。此前发现过 PWA 旧缓存等待激活的问题，更新代码后必须确认页面确实加载新缓存。

不能仅据这些检查宣称所有用户“无法删除”都由同一个 JavaScript 异常造成。本轮移除了上述明确缺口，并通过隔离测试地址实测删除到保存的完整链路。

## 界面入口

- 任务右侧常显 `⋯` → 编辑任务 / 删除任务。
- 分类右侧常显 `⋯` → 重命名分类 / 删除分类。
- 设置 → 已导入计划 → 每条计划的“删除计划”。“计划”指 TW_PLAN_V1 导入记录；已有学习路线和刷题记录功能继续保留。
- 页面上方“撤销删除”恢复最近一次；“设置 → 最近删除”查看并撤销更早的删除。删除后刷新、离线重开仍可使用。

菜单为小型原生 dialog，避免被任务卡的 `overflow: hidden` 裁掉；手机触控区域至少 44px，不依赖悬停或长按。确认成功后保留“已删除”状态，点击“完成”退出，防止双击穿透到下方任务。

## 删除边界

单条任务只删除所选日期这一次任务记录。导入多日计划和手动转入不是重复任务规则；当前没有无限重复任务模型，因此不额外搭建“本次及后续”功能。不联动删除其他日期、刷题记录或原计划。

分类删除默认将该日期任务移到“未分类”，保留 ID、顺序、备注、完成状态和来源关联；也可明确选择删除分类内全部任务。只影响所选日期。已有未分类时合并；删除未分类本身并保留任务时，需要建立新的未分类容器，确认界面会解释这一点。

整计划确认会按实际关联任务扫描，包括手动转入的实例，同时显示记录数、按 `sourceTaskId` 去重的原任务数、完成数和今日及以后未完成数。提供三种处理：

1. 默认仅删除计划记录，保留全部任务，解除来源计划关联。
2. 同时删除今日及以后未完成任务；保留过去的记录与所有已完成记录，解除剩余关联。
3. 同时删除所有关联任务（包括历史和已完成），须额外勾选明确确认。

撤销计划删除会恢复计划、被删除任务与原来源字段。已有任务标题/备注等后续修改会保留；恢复关联时如发现新的关联冲突会中止，不覆盖当前数据。手动转入处理记录保持原样，避免删除后又从昨日提示中自动生成任务。

## 数据与备份

沿用 `forward-study.v1`，内部 version 仍为 2，新增可选 `deletions` 数组。不需要清空或重置。旧数据和旧备份缺少此字段时视为空列表。

每次删除记录保存移除的任务/分类/计划、移动关系与解除的来源字段，仅保存本次所需逆操作，不保存整份应用快照。删除与副本作为同一次主数据 `setItem` 提交。撤销也一次提交；写入失败保留原主数据和原撤销记录。确认时重新检查关联内容，防止对已变化的数据执行旧确认。

撤销只针对被影响的记录，不回退整个应用；新建的无关任务、图片、路线和设置不会被覆盖。若任务、分类或关联在随后被再次删除/修改而产生冲突，请先撤销较新的操作。一次恢复遇到任意冲突就整体中止。

副本会进入完整 JSON 备份与恢复。最多保留 50 次删除；达到上限时停止新的删除，并要求先撤销或明确清理副本，不自动丢弃最早记录。副本占用本地存储；容量不足时提示保存失败，不通过清理用户数据解决。设置中“清理全部撤销副本”需二次确认，清理后不可撤销此前删除；它不删除当前任务或计划。测试未点击此永久清理操作。

## PWA

新增模型、界面脚本与 CSS 已纳入离线预缓存，缓存版本为 `v2.2.1`。不强制刷新正在编辑的页面。看到“新版本已准备好”时，完成编辑后关闭同一浏览器所有 Today Work 标签页与独立窗口，再打开原地址。无须清除网站数据，换端口也不能迁移原数据。
