# Today Work

当前本地版本为 2.4，界面、手机导航、图片与短句见 [外观说明](PERSONALIZATION.md)，轻量音效见 [音效说明](SOUNDS.md)，验证范围见 [2.4 验收](../tests/QA-2.4.md)。沿用 2.3 的 [AI 导入、预算排期和撤销流程](AI-IMPORT-2.3.md) 与 [协议](TW_PLAN_V1.md)。下文保留早期功能与迁移背景；新排期使用已有未完成任务负担，旧 Day 整体映射继续兼容。

Today Work 面向所有用户，把外部 AI 聊天中生成的学习、成长或工作计划，转化为可执行、可调整的日常任务。在自己常用的 AI 中讨论计划，复制结构化结果到 TW，即可生成计划与任务。新用户从空白任务和路线开始，已有个人任务和历史继续保留。

保持纯 HTML / CSS / JavaScript，无框架、账号、应用后端、云数据库或 AI API。任务、计划和设置保存在当前浏览器 localStorage，自定义卡片图片保存在本地 IndexedDB；PWA 只缓存公开静态资源。

当前版本 **2.2**：本轮补齐任务、分类、导入计划的删除和持久撤销，详见 [删除说明](DELETION.md) 与 [2.2 验收记录](../tests/QA-2.2.md)。既有 AI 计划导入与个性化见 [2.1 使用说明](RELEASE-2.1.md) 和 [计划协议](TW_PLAN_V1.md)。以下“导入今日计划”是保留的旧版单日功能。

## 启动与安装

### 推荐：固定本地网址

1. 安装 Node.js LTS（若电脑已有，无需再安装）。
2. 双击 `启动 Today Work.cmd`，或在项目目录运行 `node server.cjs`。
3. 用 Edge / Chrome 打开 **http://127.0.0.1:8765/**。日常请固定此地址，包括主机名和端口。
4. 设置页面显示“离线资源已就绪”后，可离线打开核心功能。
5. 在设置点击“安装 Today Work”（仅浏览器允许时出现），或点击地址栏安装图标。按浏览器提示安装到 Windows；Android Chrome 可从 HTTPS 网站菜单选择“安装应用 / 添加到主屏幕”。安装后以独立窗口显示。

本地服务只分发静态文件，不接收或保存用户数据。关闭命令行即可停止。第一次访问、安装准备、获取更新需要服务运行；核心资源缓存就绪后，即使服务停止，已缓存应用仍可打开。不要清除网站存储或离线资源。

也可使用 Python：`python -m http.server 8765 --bind 127.0.0.1`。这仍是同一个 origin，但建议使用项目的 Node 启动器，其资源类型、缓存头及公开文件范围已配置。

### 继续使用文件直开

原有 `index.html` 和 `打开学习打卡.cmd` 位置不变，仍支持文件直开。file:// 不支持 Service Worker 或 PWA 安装；本地任务、导出与恢复仍可使用。浏览器自动化不支持直接打开 file://，此方式未在自动化中实测。

## 从 file:// 搬到 PWA：先导出，再恢复

不同文件位置、127.0.0.1、localhost、端口、GitHub Pages 网站的存储空间可能不同，旧记录不会自动跨地址出现。

1. 先在**原来的文件位置和浏览器**打开更新后的 index.html。
2. 在“设置 → 导出全部数据”保存 JSON。保留这份文件。
3. 打开固定本地网址或部署后的 HTTPS 网站。
4. “设置 → 导入备份 → 选择 JSON 文件”，检查日期、任务、题目、路线概要。
5. 点击“继续恢复”，再点击“确认覆盖恢复”。
6. 恢复后检查任务、日期、进度和主题。这个过程不删除旧文件环境的存储。

若浏览器没有自动下载，可点击生成的下载链接，或展开“查看备份内容”，全选 JSON 复制到文本文件并以 UTF-8 保存为 .json。恢复窗口也支持粘贴完整备份 JSON；同样必须先解析预览并确认覆盖。

恢复前会将当前原始内容保存到 `forward-study.before-restore`，并尝试下载 `today-work-auto-backup-before-import.json`。之后也可在设置中重新导出恢复前备份。若原始内容损坏，可导出原始数据 / 迁移快照供检查。

## 每日任务与昨日未完成

- 新的一天从空白计划开始，不自动复制个人示例或昨日任务。
- 分类底部添加任务；任务和分类右侧常显“⋯”打开编辑/重命名及删除。普通勾选即时保存，不弹窗。
- 删除分类默认保留任务并移到未分类；也可明确选择同时删除任务。整计划在设置的“已导入计划”中删除，确认时说明关联数量和处理方式。
- 删除后页面上方可撤销；设置的“最近删除”支持刷新后恢复更早删除，完整备份包含撤销副本。
- 编辑任务时展开“更多信息”，可填写优先级、预计时间、实际用时与备注。高优先级优先展示，同优先级保持原顺序；已有分类设置 manualOrder 时保留人工排序。
- 今天有昨日未完成内容时，在任务上方显示可折叠卡片。逐项“加入今日 / 忽略”，或批量处理。
- 加入时保留分类，新任务未完成；今天存在同名任务则跳过。处理状态单独保存，刷新后不重复提醒。昨日任务和勾选状态不被改动。
- 可使用日期输入、上一天 / 今天 / 下一天、日历或历史列表查看具体日期。

## 导入今日计划

点击任务卡上方“导入今日计划”，粘贴如下结构，先“解析预览”，再“确认导入”：

```json
{
  "date": "2026-10-15",
  "categories": [
    { "name": "学习", "tasks": ["阅读一章", "完成练习"] },
    { "name": "复盘", "tasks": ["记录收获与下一步"] }
  ]
}
```

省略 date 使用**真实今天**，而非当前查看的历史日期；也支持其他有效日期。同名分类合并，同分类的同名任务跳过，已有完成状态不覆盖；新任务默认未完成。错误 JSON 会友好提示，不写入数据。空分类允许，空任务不允许。导入结果会列出新增分类、任务与重复项数量。

## LeetCode

- 左侧 LeetCode → 新增题目。填写题号、题名、题型、难度、状态、1–3 星熟练度、独立完成、首次完成日期、备注和可选链接。
- 支持编辑、确认删除、题号 / 题名搜索，以及题型、难度、状态、熟练度和独立完成筛选。
- 相同题号不重复建立记录，请编辑已有题目。
- 1 星或“需要复习”的题目进入待复习区域。“标记已复习”只增加次数、更新复习日期，不擅自修改熟练度或完成状态。
- 分类掌握卡按题型显示题数和平均熟练度。
- 每日任务中 LeetCode / 刷题 / 算法分类下已勾选任务可以点“加入刷题记录”。只预填题号、题名和日期，用户补充确认后才保存。不会自动强制入库。

## 学习路线

新用户没有强制默认路线。点击“路线 → 新增路线”，填写自己的目标与内容：

```text
# 基础
阅读
听力

# 实践
## 口语
完成一次对话
```

# 开头为阶段，## 为可选分组，其余每行一个知识点。每个知识点可以选未开始、学习中、已完成；阶段和总完成率按已完成知识点数量计算。空分组不影响分母。

可建立多条路线并切换，适用于任意目标。编辑时相同阶段、分组及知识点保留进度；移除知识点前需确认。删除整条路线也需确认。旧数据中已有的个人路线继续保留。

## 记录与统计

历史记录显示分类、完成数、完成率、是否全部完成，以及填写过的实际学习时长。点击进入当天。

周以周一为开始日，周 / 月完成率使用对应期间完成任务数除以总任务数；未来计划不计入学习统计。时长按实际用时累计，不使用预计时间替代；没有实际用时的期间不显示 0 分钟卡片。

至少完成一项任务视为学习一天。今天尚未打卡时，连续天数允许延续至昨天；历史最佳按全部已发生记录计算。第 X 天为开始日期到今天的自然日差 + 1。取消完成或删除任务后统计随实际记录重算。

## 数据结构、迁移与保护

核心键保持 `forward-study.v1`，**键名不改，内部 version 升级为 2**。保留原有 `startDate` 和 `days[日期].categories[].tasks[]`，新增：

- carryOverHandled：按今日日期记录昨日任务 ID 的 added / ignored 状态。
- leetcode：长期刷题记录列表。
- routes：数据驱动的路线 / 阶段 / 分组 / 知识点。
- settings.theme：light / dark / system。
- plans（可选）：TW_PLAN_V1 原计划、执行规则、Day → 日期映射。旧数据自动视为空列表。
- 任务的 sourcePlanId、sourceDay、sourceTaskId（可选）：保留导入来源，手动转入时不改变原逻辑任务身份。
- settings.personalization（可选）：短句、左右卡片设置；图片内容存入本地 IndexedDB。
- deletions（可选）：任务/分类/导入计划的删除逆操作副本，删除和撤销均与主数据一起保存。
- 任务的 priority、estimatedMinutes、actualMinutes、note 均可选。

首次迁移会在写入升级数据前保留原文到 `forward-study.backup.v1`。旧 `forward-study.theme` 不删除，旧主题会迁入 settings。PWA 不增加个人数据字段，也不搬动 / 上传 localStorage。

异常单条记录会被隔离，修改前保留带时间戳的 `.recovery.*` 原始快照；完全无法解析或遇到未知版本时进入只读保护，可继续打开页面并恢复有效备份。迁移备份无法保存时不覆盖原文。应用不会调用 localStorage.clear()。

备份导出格式包含 app、backupVersion、exportedAt、data，以及可选 imageAssets，支持不含计划和图片的旧备份。恢复先暂存图片，再以一笔主数据键写入提交；快照或保存失败则停止恢复并撤销本次暂存图片。

## PWA 文件与更新

- `manifest.webmanifest`：Today Work 名称、standalone、相对 start_url / scope、主色。
- `service-worker.js`：只预缓存应用 HTML、CSS、JS、图标和 manifest，不缓存备份或个人记录。
- `js/pwa.js`：注册、安装按钮、文件环境降级、更新提示。
- `icons/`：192 / 512 PNG，192 / 512 maskable PNG、180 Apple Touch Icon；靛蓝底色、白色 TW 正式字标，**无需另准备 Logo**。SVG 源文件与可选生成脚本一并提供。

修改静态代码后递增 service-worker.js 中的 CACHE_VERSION。新缓存完整安装后等待旧窗口关闭，再激活并清理**当前路径下本应用**的旧缓存，不删除其他应用缓存。无强制重载，不中断正在编辑的数据。

验证离线：联网打开一次 → 设置确认“离线资源已就绪” → 关闭网页 → 停止本地服务或断网 → 再打开同一地址 → 检查任务勾选、刷题、路线、统计与设置。恢复服务 / 网络后无需迁移数据。

## GitHub Pages

执行 `powershell -File tools/prepare-pages.ps1`，得到 dist/ 的公开静态文件。此步骤只是打包，不会上传或部署。

1. 将 dist/ 的**内容**放到一个 GitHub 仓库的发布分支根目录。
2. 仓库 Settings → Pages，选择该分支与 /(root)，保存。
3. 访问 GitHub 提供的 HTTPS 地址，例如 https://username.github.io/today-work/。
4. 等待离线资源就绪，通过设置或浏览器菜单安装。

所有资源、manifest、start_url、scope 和 Service Worker 使用相对路径，支持仓库子路径。不要把本地导出、test-artifacts/、backups/ 等放进发布内容。`prepare-pages.ps1` 只收集公开文件；个人记录始终留在各访问者自己的浏览器中。
